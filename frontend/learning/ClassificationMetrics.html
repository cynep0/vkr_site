Метрики качества для классификации

Как оценить, насколько хорошо модель различает классы?

Зачем нужны метрики?

В задачах классификации простого подсчета правильных ответов недостаточно. Метрики помогают понять:

  • Насколько модель уверена в своих предсказаниях
  • Какие типы ошибок она совершает чаще
  • Как модель ведёт себя на несбалансированных данных
  • Какой порог классификации выбрать для конкретной задачи
Важно: В классификации «лучшая» метрика зависит от того, какая ошибка дороже: ложное срабатывание или пропуск цели.

Матрица ошибок (Confusion Matrix)

Матрица ошибок — это таблица, которая показывает, как модель перепутала классы. Это основа для всех остальных метрик.

TP (True Positive): Модель правильно предсказала положительный класс
TN (True Negative): Модель правильно предсказала отрицательный класс
FP (False Positive): Ложное срабатывание (ошибка 1-го рода)
FN (False Negative): Пропуск цели (ошибка 2-го рода)

Основные метрики классификации

1. Accuracy (Точность)

Accuracy = (TP + TN) / (TP + TN + FP + FN)

Доля правильных предсказаний среди всех предсказаний.

Интерпретация: Простая и понятная метрика. Проблема: Вводит в заблуждение на несбалансированных данных (если 95% класса 0, модель с 95% accuracy может просто всегда предсказывать 0).

2. Precision (Точность предсказания положительного класса)

Precision = TP / (TP + FP)

Среди всех объектов, которые модель назвала положительными, какая доля действительно положительна?

Когда важна: Когда ложные срабатывания (FP) дороги.
Пример: спам-фильтр — лучше пропустить спам, чем удалить важное письмо.

3. Recall (Полнота, Sensitivity)

Recall = TP / (TP + FN)

Среди всех реально положительных объектов, какую долю модель нашла?

Когда важна: Когда пропуск цели (FN) критичен.
Пример: диагностика болезни — лучше ложная тревога, чем пропуск заболевания.

4. F1-Score (Гармоническое среднее)

F1 = 2 × (Precision × Recall) / (Precision + Recall)

Баланс между Precision и Recall. Достигает максимума, когда обе метрики высоки.

Преимущество: Одна метрика вместо двух. Недостаток: Не учитывает TN (может быть проблемой при сильном дисбалансе).

5. ROC-AUC (Площадь под ROC-кривой)

ROC-кривая показывает компромисс между TPR (Recall) и FPR при разных порогах классификации.

AUC (Area Under Curve) — площадь под этой кривой.

Интерпретация:
  • AUC = 1.0 — идеальная модель
  • AUC = 0.5 — модель не лучше случайного угадывания
  • AUC < 0.5 — модель «вредная» (инвертируйте предсказания)
Преимущество: Не зависит от порога классификации, устойчив к дисбалансу.

Какую метрику выбрать?

Выбор метрики зависит от бизнес-контекста и цены ошибок.

Используйте Accuracy, если:

  • Классы сбалансированы
  • Ошибки FP и FN одинаково нежелательны
  • Нужна простая метрика для отчёта

Используйте Precision, если:

  • Ложные срабатывания (FP) дороги
  • Пример: спам-фильтр, кредитный скоринг

Используйте Recall, если:

  • Пропуск цели (FN) критичен
  • Пример: диагностика, обнаружение мошенничества

Используйте F1-Score, если:

  • Нужен баланс между Precision и Recall
  • Хотите одно число для сравнения моделей

Используйте ROC-AUC, если:

  • Есть дисбаланс классов
  • Важно качество ранжирования (вероятностей)
  • Порог классификации будет подбираться позже
Рекомендация: Всегда смотрите на матрицу ошибок и несколько метрик. Одна метрика может скрывать важные проблемы.

Пример расчёта метрик

Дано: Матрица ошибок для бинарной классификации:

Предсказано
Реально TP = 80 FP = 20
FN = 10 TN = 90

Расчёт:

  • Accuracy = (80 + 90) / 200 = 0.85 (85%)
  • Precision = 80 / (80 + 20) = 0.80 (80%)
  • Recall = 80 / (80 + 10) = 0.89 (89%)
  • F1-Score = 2 × (0.80 × 0.89) / (0.80 + 0.89) ≈ 0.84

Интерпретация: Модель хорошо находит положительные объекты (Recall 89%), но иногда ошибается (Precision 80%). F1 = 0.84 — хороший баланс.
